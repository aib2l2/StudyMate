# Изменения

## 2.2.0 — 11 ноября 2026

Четыре новые возможности. Сценарий защиты 2.1 и данные сохранены: настоящая demo-база 2.1 обновляется миграциями 005–008, это проверено тестом.

### A. Чат встречи и живые обновления
- Шина событий в процессе: события публикуются только после commit. Поток SSE `/api/events` с одноразовым билетом вместо токена в URL; поток не держит транзакцию и закрывается при выходе или смене пароля.
- Переписка на странице встречи: только для участников, команда её не читает. Идемпотентная отправка, «Прочитано», счётчик непрочитанных, одно уведомление на пачку, ограничение частоты, экспорт своих сообщений.
- Опрос сервера раз в 60 секунд при живом потоке (раньше раз в 12 секунд).

### B. Поиск, избранное, рекомендации
- Полнотекстовый поиск FTS5 с запасным путём LIKE; ввод очищается. Вариант «Любая тема».
- Сортировка по ближайшему времени, цене и байесовскому рейтингу.
- Избранные менторы: звёздочка в каталоге и анкете, раздел в кабинете.
- Лист ожидания оповещает о новом или освободившемся подходящем времени.
- «Вам может подойти»: правила с объяснением каждой рекомендации, без машинного обучения.

### C. Умный календарь
- Недельные серии на 2–12 недель; конфликтующие недели пропускаются; «Закрыть всю серию».
- Перенос встречи по согласию обоих: id, заметки, чат и цена сохраняются, напоминание переносится.
- Экспорт одной встречи и всех встреч в `.ics` (RFC 5545).

### D. Групповые занятия
- Слот на 2–5 мест с темой, ценой за место и минимумом участников; одна запись на студента; запись подтверждается сразу.
- Вместимость гарантирует триггер SQLite; гонка за последнее место покрыта тестом.
- Общие ссылка, аудитория и материалы, личные заметки у каждого свои; чат группы; завершение ментором один раз, XP ментору один раз.
- Автоотмена за 2 часа при недоборе; отмена всей группы ментором.

### Прочее
- Демоданные 2.2 добавляются идемпотентно, в том числе в существующую demo-базу.
- pytest: 60 → 112, Vitest: 13 → 28, Playwright: 2 → 5. Регрессионный тест миграций на настоящей базе 2.1.

### Сознательно не сделано
- Шина событий работает внутри одного процесса; для нескольких процессов нужен внешний брокер.
- Подписка на календарь по секретной ссылке: это долгоживущий токен в URL.
- Перенос групповых занятий: у группы несколько участников, согласие всех — отдельная задача.
- Табличные CHECK для групповых полей на уже существующих базах: SQLite не добавляет их через ALTER, правила соблюдает сервис.
- Повторный выбор ментором цены для каждой недели серии: в серии одна цена.
- 6 предупреждений `exhaustive-deps` остаются по той же причине, что в 2.1.


## 2.1.0 — 11 ноября 2026

Сценарий защиты, данные в `data/*.sqlite3` и визуальная концепция сохранены. Миграция `004` только добавляет таблицу.

### 1. Читаемость кода
- Бэкенд отформатирован `ruff format` (длина строки 100), `ruff check` настроен в `pyproject.toml`. Инструменты разработки вынесены в `requirements-dev.txt`.
- `api.py` (около 730 строк, все эндпоинты внутри одной функции) разбит на `schemas.py`, `deps.py` и `routes/` (auth, public, account, mentor, bookings, quiz, admin). `create_app` только собирает приложение.
- У всех эндпоинтов есть Pydantic-модели ответа. `/docs` и `docs/openapi.json` описывают реальные ответы, сам JSON не изменился.
- Фронтенд: Prettier и ESLint (typescript-eslint, react-hooks). `styles.css` больше не сжат в 12 строк. `views.tsx` и `workspace.tsx` разбиты на `pages/` (10 экранов) и `components/`.
- `npm run gen:api` генерирует типы из OpenAPI, а `api-contract.ts` проверяет их совместимость с `types.ts`. Проверка сразу нашла расхождение: у тем в карточке ментора нет поля `code`.

### 2. Корректность и производительность бэкенда
- GET-запросы больше не берут блокировку записи SQLite (`BEGIN IMMEDIATE`). Чтение идёт через отдельную сессию-снимок с защитой от записи, запись — по-прежнему сериализована.
- PBKDF2 (600 000 итераций) при регистрации, входе, смене и сбросе пароля вычисляется вне транзакции записи.
- Ограничение попыток входа считается по паре «адрес + email» и по адресу отдельно. Раньше одна общая очередь на `127.0.0.1` позволяла одному человеку закрыть вход всем. Словарь попыток очищается.
- Истёкший токен удаляется при первом запросе с ним.
- Добавлены заголовки `Content-Security-Policy` и `X-Frame-Options: DENY`.
- Новые тесты изоляции: чужой пользователь получает 403 и не видит чужие данные по встречам, тестам, оплате, отзывам и admin-эндпоинтам.

### 3. Новые функции (работают офлайн)
- Смена пароля: требуется текущий пароль, остальные сессии завершаются.
- «Выйти на всех устройствах».
- Восстановление доступа: `python -m studymate reset-password --email …` выдаёт одноразовый код на 30 минут, пользователь вводит его на странице `/reset`.
- Выгрузка своих данных в JSON (`GET /api/me/export`).
- Миграция `004_account_security`: таблица `password_reset_codes`.

### 4. Фронтенд и доступность
- Вкладка «03 / Безопасность и данные» в кабинете и страница «Забыли пароль?».
- Опрос сервера не идёт в скрытой вкладке; при возвращении на вкладку данные обновляются сразу.
- Ошибки форм связаны с полями (`aria-describedby`, `aria-invalid`). Диалог возвращает фокус на кнопку, которая его открыла. Звёзды рейтинга получили `aria-pressed`, варианты ответа в тесте — `value`.
- Палитра светлой темы доведена до WCAG AA: рыжий `#cc4e2d` заменён на `#bd472a`, серый `#74756e` — на `#6b6c65`.
- `localStorage` и `sessionStorage` обёрнуты в try/catch: в приватном режиме сайт не падает.

### 5. Тесты и CI
- pytest: 40 → 60 тестов, `pytest-cov` с порогом 90% (сейчас 92,8%).
- Vitest и Testing Library: 13 тестов (`api.ts`, форма входа и сброса пароля, панель безопасности).
- Playwright: сценарий защиты целиком на временной demo-базе.
- `./scripts/test.sh` и `.github/workflows/ci.yml` выполняют одни и те же проверки.

### Сознательно не сделано
- Пакет `httpx2`, который советует предупреждение Starlette, не установлен: он ещё не устоялся. Предупреждение отфильтровано.
- 6 предупреждений `react-hooks/exhaustive-deps` оставлены: эффекты специально зависят только от ключевых значений (подробнее в `docs/VERIFICATION.md`).
- Токен сессии остаётся в `sessionStorage`. Причины и что нужно для публичного запуска (httpOnly-cookie, CSRF, HTTPS, распределённое ограничение попыток) — в `docs/ARCHITECTURE.md`.
- Подтверждение email, письма, реальная оплата и видеосвязь не добавлены: проект должен работать без интернета и внешних сервисов.
- Код сброса выдаётся командой только при остановленном сайте, как и назначение роли команды: CLI берёт ту же блокировку базы, что и сервер.
- GitHub Actions в настоящем репозитории не запускался.
